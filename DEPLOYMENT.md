# Инструкция по деплою на хостинг

## ✅ Быстрый деплой (всё работает автоматически)

1. **Соберите проект:**
   ```bash
   npm run build
   ```

2. **Загрузите содержимое папки `build/` на хостинг**

3. **Готово!** Всё будет работать, потому что:
   - Токен встроен в JS код во время сборки
   - PHP прокси имеет fallback на токен по умолчанию

## 🔒 Рекомендуемый способ (для безопасности)

Для большей безопасности рекомендуется создать конфиг-файл на сервере:

1. **После загрузки build на хостинг**, создайте файл `telegram-config.php` в корне сайта (рядом с `telegram-proxy.php`)

2. **Скопируйте содержимое из `telegram-config.php.example`** и укажите ваш токен:
   ```php
   <?php
   return [
       'BOT_TOKEN' => 'ваш_токен_здесь',
   ];
   ```

3. **Удалите fallback из `telegram-proxy.php`** (строки 47-51) для большей безопасности

## 📋 Что попадает в build:

- ✅ Все статические файлы (JS, CSS, изображения)
- ✅ `telegram-proxy.php` - прокси для отправки сообщений
- ✅ `telegram-config.php` - конфиг (если был создан)
- ✅ `telegram-config.php.example` - пример конфига
- ✅ `.htaccess` - для работы роутинга
- ✅ `_redirects` - для Netlify

## ⚠️ Важно:

- Файл `.env` **НЕ** попадает в build (это нормально)
- Переменные из `.env` встраиваются в JS код во время сборки
- Токен виден в JS коде (это нормально для клиентских приложений)
- Для максимальной безопасности используйте `telegram-config.php` на сервере

## 🧪 Проверка после деплоя:

1. Откройте сайт в браузере
2. Заполните форму обратной связи
3. Отправьте тестовое сообщение
4. Проверьте, что сообщение пришло в Telegram

Если что-то не работает - проверьте консоль браузера (F12) на наличие ошибок.
